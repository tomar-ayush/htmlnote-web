Web workspace for **HTMLNote** — an agent-first, multi-tenant HTML notebook where rich `.html` documents generated by LLMs or humans live directly inside your own S3-compatible object storage.

Companion backend repository: **[tomar-ayush/htmlnote-api](https://github.com/tomar-ayush/htmlnote-api)**

---

## Why HTML Instead of Markdown?

Agents and LLMs produce vastly cleaner structured layouts, tables, styled callouts, SVG diagrams, and embedded blocks in **HTML** than in constrained Markdown dialects. HTMLNote treats `.html` as a first-class editable page format rather than a second-class export:

- **Native HTML Canvas**: Edits full HTML documents inside an isolated same-origin `<iframe>` without lossy Markdown AST round-tripping.
- **Ribbon Toolbar**:
  - **Home**: Font family, size, bold/italic/underline/strikethrough, text & highlight swatches, lists, alignment, undo/redo.
  - **Insert**: Links, images, code blocks, checklists, horizontal dividers, timestamps, and interactive tables (`TableTools`).
  - **Draw**: Inline SVG freehand pen, highlighter, and eraser strokes embedded cleanly in the page HTML.
  - **Design**: Inspect and customize element tags, CSS classes, spacing, borders, and page styles.
  - **History**: Compare and restore up to 10 automatic/manual `.html` revisions, open sandboxed previews, or download `.html` files.
- **Bring-Your-Own Object Storage UI**: Configure **Cloudflare R2**, **Backblaze B2**, **AWS S3**, or any **Custom S3** endpoint directly in the UI with live connection verification before saving.
- **Drag-and-Drop `.html` Import**: Drop existing `.html` / `.htm` files straight into any section.
- **Zero Bloat**: React 19 + TypeScript with zero third-party UI or state libraries (~85 KB gzipped JS bundle).

## How Vercel Proxying Works

Because the HTMLNote editor reads `iframe.contentDocument` directly and relies on `__Host-` session and CSRF cookies, the frontend and backend must share an origin in the browser.

During Vercel builds, [`build-vercel.mjs`](build-vercel.mjs) emits Vercel's **Build Output API v3** manifest (`.vercel/output/config.json`) using the `BACKEND_URL` environment variable configured in Vercel so `/api/*`, `/page/*`, and `/view/*` proxy transparently to Cloud Run while static assets and SPA routes resolve directly on Vercel Edge.

## Local Development

Start the backend (`tomar-ayush/htmlnote-api`) on port `8000`, then run:

```bash
npm ci
npm run dev
```

`vite.config.ts` proxies `/api`, `/page`, and `/view` to `http://127.0.0.1:8000` automatically.

Type-check and build production assets locally:

```bash
npm run typecheck
npm run build
```

## Deploying to Vercel (Git Integration)

1. Import **`tomar-ayush/htmlnote-web`** into Vercel (Vercel reads `vercel.json` automatically).
2. Under **Project Settings -> Environment Variables**, add:

| Name | Value |
|---|---|
| `BACKEND_URL` | Your deployed Cloud Run URL (e.g. `https://htmlnote-api-xyz.a.run.app`) |

3. Deploy. Every push to `main` builds with Vercel's native CI and wires `/api/*`, `/page/*`, and `/view/*` directly to `BACKEND_URL`.
4. After your Vercel domain is live (e.g. `https://htmlnote-web.vercel.app`), set `ALLOWED_ORIGINS` on your **Cloud Run** service (`htmlnote-api`) to include your Vercel origin(s) so CSRF/Origin validation permits proxied write requests.
